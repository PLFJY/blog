tags:

那天本来想删个日志，进到恢复环境在 Data 分区的根目录执行了一个命令

```zsh
rm -rf /var/log/ *
```

我反应过来的时候已经丸辣，多了个空格，我还说怎么就出现了 Applications 目录内的文件的权限报错记录，说是删不掉，我看到的时候感觉不对劲立刻 Ctrl+C 停掉了，不过不出意外，就是 a 开头的文件和第一个 a 开头的文件夹里面的东西已经🈚️了，所幸系统还能进去，不过已经有诸如装不上 Roseeta 之类的问题了

于是，沉思了一下之后我决定重装系统，我原先以为重装的时候是会正常给我迁移 Users/ 下的用户，结果！没迁移过来！然后我又鬼使神差的在 OOBE 里面给创建了一个名字不一样的 rescue 用户，此时这个 rescue 成了 501；弄完了，猛然发现不对劲，然后又创建了与以前用户同名的用户 plfjy，id: 502，一切就从这里开端了，我把以前的用户文件夹迁了过来，然后把全盘加密之类的其余系统权限全部交给了 502，转手给 rescue 删了。殊不知噩梦才刚刚开始

之后就是，由于以前的用户家目录下都是 id: 501 的数据，出现了不少用户权限的问题，然后我又双叒叕在 502 的情况下重新安装了一大堆软件，然后迁移了以前的 homebrew 目录，也是 501 权限的；之后就是感觉不对了，去恢复环境里面把 502 的用户 id 改成了 501，并用 chrown 把 Users/plfjy 下的所有新文件全部夺舍回了 501 不过这一下，我给忘记了两件中要的事情：用 chrown 把/Applications 和 /opt/homebrew 里面的东西夺舍回 501

然后就是用 brew 的时候发现了不对劲，把 /opt/homebrew 下的夺舍回 501，不过我从来没往 /Applications 目录那方面去想，直到我反复发现，有很多的软件没法正确的存储一些自身状态的时候开始着手排查

从根目录扫了一下，这一扫不要紧，一大堆 502 的文件，我人都傻了，并且系统相关的一大堆东西还最好别动，因为系统索引一类的可能会依赖这些东西；最关键的是 /Applications 下的几乎清一色的 502，原来这才是原因；后来就是我给这个夺舍回了 501 才最终处理完收尾工作

所以这个故事告诉我们， rm -rf 的时候记得检查空格，我要累死了

写完发现纯流水账来的，不管了 : )
